Big crowds tanking your frames? [b]Siesta[/b] puts off-screen, far-away NPCs to sleep - hiding them and pausing their movement, schedule and vision - then wakes them cleanly as you get close. It works on [b]every NPC in the world[/b], including ones added by other mods. Built on [url=https://github.com/ifBars/S1API]S1API[/url].

[size=4][b]Features[/b][/size]
[list]
[*][b]Distance + visibility LOD for every NPC.[/b] Off-screen NPCs beyond a configurable distance are hidden (no render/animation cost); farther, idle, non-essential ones are also deep-culled - their movement, schedule and 10Hz vision/awareness sweep are all paused, which is where most of the per-NPC cost actually is.
[*][b]Functionality first.[/b] Dealers attending a deal, employees mid-task, customers in a deal or awaiting delivery, police officers, anyone in a conversation, in a vehicle, knocked out or indoors are never deep-culled - only ever hidden. Nothing essential is skipped.
[*][b]Clean wake-up.[/b] A woken NPC has its vision, movement and schedule restored in the order that keeps it from standing inert, catches up to the current in-game time, and is only shown again once it is safely back on the NavMesh. A wake that fails leaves the NPC fully running and is retried automatically.
[*][b]Multiplayer safe.[/b] Hiding is purely local per client; the deeper movement/schedule/vision pausing runs only on the host, who owns NPC simulation, so there is no desync.
[*][b]Cheap and self-tuning.[/b] A small, fixed number of NPCs is re-checked per frame, so the mod's own cost stays flat regardless of how many NPCs exist.
[*][b]Works with anything that adds NPCs[/b] - base game, employee mods, NPC-overhaul mods. Every NPC registers in the same game NPC registry, so modded NPCs get the same treatment.
[/list]
[size=4][b]How much FPS will I gain?[/b][/size]
The win scales with how many NPCs are far from you - biggest in NPC-dense saves and small in a sparse spot, because NPC simulation isn't always the dominant frame cost. Siesta only ever removes work for NPCs you aren't looking at, so it's a safe, free-when-idle optimization.

[size=4][b]Installation[/b][/size]
[b]Vortex:[/b] install the archive as-is - the release ZIP ships [font=Courier New]Siesta.dll[/font] under [font=Courier New]mods/[/font], so the Schedule I extension deploys it correctly. Install MelonLoader and S1API first.

[b]Manual:[/b]
[list=1]
[*]Install MelonLoader 0.7.3 or newer for Schedule I.
[*]Install S1API (ifBars/S1API_Forked) - its DLLs go in [font=Courier New]Mods/[/font] and [font=Courier New]Plugins/[/font] per its own instructions.
[*]Drop [font=Courier New]Siesta.dll[/font] into your Schedule I [font=Courier New]Mods[/font] folder.
[*]Launch the game.
[/list]
[size=4][b]Settings[/b][/size]
All settings live in [font=Courier New]UserData/MelonPreferences.cfg[/font] under [font=Courier New]Siesta_01_Main[/font] and apply live: [font=Courier New]EnableLod[/font] (master on/off), [font=Courier New]EnableInMultiplayer[/font], [font=Courier New]CosmeticDistance[/font] (40m - hide off-screen NPCs beyond this), [font=Courier New]DeepDistance[/font] (80m - also pause movement/schedule/vision beyond this, host-only), [font=Courier New]Hysteresis[/font] (8m), [font=Courier New]BudgetPerFrame[/font] (32), [font=Courier New]UseCosmeticCull[/font], [font=Courier New]UseDeepCull[/font], [font=Courier New]RespectOnScreen[/font], [font=Courier New]ShowFpsCounter[/font].

[size=4][b]Compatibility[/b][/size]
[list]
[*]Multiplayer: cosmetic hiding runs locally on every client and is always safe. The deeper movement/schedule/vision pausing only ever runs on the host, who owns NPC simulation - clients never touch it, so there is no desync. Set [font=Courier New]EnableInMultiplayer[/font] to off to disable the mod entirely in co-op.
[*]Save-safe: every NPC is restored to fully vanilla before any save, scene change, application quit or mod unload, so a save file never contains a culled NPC. Removing the mod is safe at any time.
[*]Works with any mod that adds NPCs - they all register in the same game NPC registry, so modded NPCs get the same LOD treatment.
[*]Fannso's MoreNPCs: its CrossCompat/Mono build ships one watcher that cannot run on a standard IL2CPP install and would otherwise flood the log with exceptions. Siesta detects the failure once and stops calling that one watcher for the session - the rest of MoreNPCs is untouched. On a matching build nothing is ever affected.
[*]IL2CPP build only (current Steam public branch).
[/list]
